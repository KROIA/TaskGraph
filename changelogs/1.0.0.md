# 1.0.0 — 2026-07-30

Working entry — not yet released. Core scheduler rewrite for concurrency safety, cooperative control, and Qt GUI-thread integration.

## Security

| Tag | Change |
|---:|---|
| ![bugfix] | <details><summary>All shared scheduler state is now mutex-guarded (ISS-001)</summary><br>`m_tasksToProcess` deque access was previously racy across the async runner and worker threads. All access now happens under the scheduler mutex; condition-variable notifications are issued after the lock is released.</details> |
| ![bugfix] | `runTask()` uses CAS `Pending`->`Running` to prevent double-run (ISS-002) |
| ![bugfix] | Destructor joins the async runner thread before pool teardown (ISS-003) |
| ![bugfix] | `runTasks` early-return paths reset `m_isRunning` via scope guard (ISS-004) |
| ![bugfix] | `runTasksAsync` uses `compare_exchange_strong` for the running flag (ISS-005) |
| ![bugfix] | Worker threads spawned lazily — no eager pool spin-up (ISS-006) |
| ![bugfix] | Dependencies stored as `std::weak_ptr` to break `shared_ptr` cycles (ISS-007) |
| ![bugfix] | Edge-time cycle detection in `Task::addDependency` (ISS-018) |
| ![bugfix] | Graph mutation rejected with `Error::busy` while the scheduler is running (ISS-009) |
| ![bugfix] | `m_lastError` is now `std::atomic<Error>` (ISS-011) |
| ![bugfix] | `getDependencies()` returns by value under the lock (ISS-012) |

| ![improvement] | <details><summary>Scheduler auto-resets terminal tasks on re-run (DEC-002)</summary><br>`runTasksBody()` now resets any `Done`/`Failed`/`Cancelled` tasks back to `Pending` at run start, so a graph can be re-run after cancel or completion without a manual `resetTasks()` call.</details> |
| ![bugfix] | <details><summary>`~TaskScheduler()` cancels in-progress run and disconnects before joining workers</summary><br>Previously, destroying a scheduler with a running graph could crash because worker threads outlived the scheduler object. The destructor now calls `cancel()` + `disconnect()` before joining.</details> |
| ![bugfix] | Force-emit `progressChangedF(1.0f)` on successful completion path so final progress is deterministically 1.0 (ISS-029) |
| ![feature] | `TaskScheduler::removeTask(shared_ptr<Task>)` — removes a task when idle, detaches it from other tasks' dependency lists, rejects while running |
| ![feature] | <details><summary>`TaskScheduler::setContextFactory` — pluggable app-supplied `TaskContext` (T-018)</summary><br>`using ContextFactory = std::function<std::unique_ptr<TaskContext>(Task*, TaskScheduler*)>`. When set, the scheduler builds the consumer's `Derived : TaskContext` per task-run and passes it to the body as a base `TaskContext&` (bodies downcast). `TaskContext` gains a `virtual ~TaskContext()`. One context per task-run, reused across the task's retry sequence. Factory runs on the worker thread — must be concurrency-safe. Pass `{}` to clear. Backward compatible (no factory = base context, byte-identical); `Task`/`TaskScheduler` remain non-template `QObject`s.</details> |
| ![feature] | <details><summary>`TaskGraphWidget` runtime viewer + visual-config API</summary><br>`setReadOnly(bool)` / `isReadOnly()` / `readOnlyChanged(bool)` lock a live widget to a pure viewer (editing hidden, run controls disabled) without rebuilding it. `setVisualConfig(const GraphVisualConfig&)` / `visualConfig()` restyle the view at runtime.</details> |
| ![feature] | <details><summary>`GraphVisualConfig` — visual theme struct (`gui/GraphVisualConfig.h`)</summary><br>Configures every view color (background, node border/text, per-status fills, edge line/arrow, highlight in/out, debug markers) plus the edge-routing waypoint style (`ColumnWaypointMode::TwoEdges`\|`OneCenter`, and per-waypoint `*Exact` interpolate-vs-steer flags). Ships `light()` (default) and `dark()` presets.</details> |
